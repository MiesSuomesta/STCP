STCPv2 native P2P phase 2 - exact libp2p Noise XX probe
========================================================

Apply as an overlay over the SAME trees used for phase 1:

  module/*      -> STCPv2/kernel/module/
  application/* -> Zephyr application root

What is added
-------------
* ABI bumped to 2.
* no_std-compatible ed25519-compact dependency (default features disabled).
* Noise protocol name: Noise_XX_25519_ChaChaPoly_SHA256.
* Exact XX initiator token order: e / e,ee,s,es / s,se.
* Noise 2-byte big-endian message framing.
* Noise SHA-256 HKDF chaining state + ChaChaPoly via existing STCP crypto FFI.
* libp2p NoiseHandshakePayload protobuf codec.
* libp2p PublicKey protobuf Ed25519 codec.
* Signature domain: "noise-libp2p-static-key:" + X25519 static public key.
* Ed25519 identity signature verification for the remote golden peer.
* New shell probe: stcp p2p noise

The probe intentionally stops immediately after Noise XX completes.  Yamux is
NOT faked.  Therefore stcp_p2p_core_ready() remains 0 and normal p2p ping /
throughput backends remain disabled until phase 3.

Build note
----------
Cargo.toml now adds:

  ed25519-compact = { version = "2.3.1", default-features = false }

Cargo.lock is intentionally not included in this overlay; the build updates it
from the actual toolchain/dependency resolver in the STCP tree.

Test
----
1. Start the golden rust-libp2p STCP server on 192.168.1.20:19010.
2. On Zephyr:

   stcp p2p show
   stcp p2p noise

Expected show after rebuild:

  P2P core    : linked ABI=2 selftest=PASS (0)
  Noise core  : XX+identity linked selftest=PASS (0)
  P2P backend : protocol not ready (Yamux/ping pending)

Expected Noise probe progression:

  P2P Noise probe: STCP 192.168.1.20:19010
    multistream : PASS
    /noise      : PASS
    Noise XX m1 : TX 32 bytes
    Noise XX m2 : RX ... bytes
    Noise XX m3 : TX ... bytes
  Noise XX + libp2p identity: PASS
  Golden peer authenticated; Yamux negotiation is the next phase.

Security note
-------------
The application probe uses a deterministic BENCHMARK identity seed so repeated
tests are reproducible.  This key is only for the interoperability probe and
MUST NOT be treated as a production device identity.  The Noise static X25519
key is still generated by the existing target crypto RNG for each probe.
